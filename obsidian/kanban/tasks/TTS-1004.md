## 🟢 TTS-1004: เปลี่ยน ?say prefix command เป็น slash command /say

Status: Review
Priority: High

### Summary
ย้ายคำสั่ง say ของ Discord say-bot จาก prefix command `?say` (message-based) ไปเป็น application slash command `/say` ลบ `?say` ออกทั้งหมด — ใช้ slash อย่างเดียว

Round 2 (ขยาย scope): slash param พิมพ์ newline ไม่ได้ → multi-line regression จาก `?say` เดิม แก้โดยเพิ่ม option `file` (`.txt` attachment) เป็นทางเข้าสำหรับข้อความหลายบรรทัด; `text` เหลือไว้สำหรับบรรทัดเดียว

### Context
- ไฟล์หลัก: `discord_say_bot.py` ปัจจุบันใช้ `commands.Bot` + `@bot.command(name="say")` (TTS-1001)
- ต้องเปิด privileged "Message Content Intent" ใน Developer Portal เพราะ prefix command ต้องอ่านข้อความ — พอเปลี่ยนเป็น slash command แล้วจะไม่จำเป็นต้องใช้ intent นี้อีก (ลด dependency กับ portal setting)
- Behavior ปัจจุบันที่ต้องคงไว้ (TTS-1002/TTS-1003): รับหลายบรรทัด (array of lines), auto mood จาก emoji, `--mood <preset>`, ลิมิต MAX_CHARS ต่อบรรทัด, คิวเล่นเสียงต่อ guild, SAY_SENTENCE_GAP_S, VC idle timeout

### Decisions (ผู้ใช้ยืนยันแล้ว)
1. **ลบ ?say ทิ้ง** — ใช้ /say อย่างเดียว ไม่มี transition period
2. **Ephemeral reply สำหรับ error/usage** (มองเห็นเฉพาะคนสั่ง) — success แจ้งใน channel ปกติ
3. **Multi-line ผ่าน `.txt` attachment** (Round 2, 2026-08-30) — `/say` เพิ่ม option `file` (`discord.Attachment`, optional); `text` เปลี่ยนเป็น optional; ต้องระบุ `text` หรือ `file` อย่างใดอย่างหนึ่ง (XOR) — ไม่มี/มีทั้งคู่ → ephemeral error. `text` = บรรทัดเดียว, `file` = หลายบรรทัด (newline จริงในไฟล์). ปฏิเสธ `||` separator
4. **ลิมิต 300 ตัว/บรรทัดคงเดิม** (Round 2) — ไม่เปิด auto-chunk; บรรทัดใดใน `.txt` เกิน MAX_CHARS → reject ทั้ง batch + เลขบรรทัด (ephemeral) เหมือน `text` path

### Scope
- Refactor `discord_say_bot.py`:
  - เปลี่ยนจาก `commands.Bot` เป็น `discord.Client` (หรือ `commands.Bot` ที่ไม่ใช้ prefix) + register slash command ผ่าน `discord.app_commands` (`@app_commands.command(name="say")` / `Tree`)
  - Slash command option: `text` (string, จำเป็น), `mood` (optional choice จาก `MOOD_PRESETS` — ได้ autocomplete/choice dropdown ฟรี แทน `--mood` flag)
  - Sync command tree ตอน on_ready (guild-specific sync จะเห็นทันที ไม่ต้องรอ global propagation สูงสุด 1 ชม.)
  - ลบ `_parse_say_args` (regex `--mood`) เพราะ option parser ของ slash จัดการให้
  - ลบ `intents.message_content` และ docstring ส่วน prefix/Message Content Intent
- Ephemeral: error/usage → `interaction.response.send_message(..., ephemeral=True)`; success → แจ้ง channel ปกติ
- คง reuse เดิมจาก `qwen_clone_tts.py` (MAX_CHARS, MOOD_PRESETS, _try_daemon, resolve_instruct) และ `say_moods.py`; TTS ผ่าน `asyncio.to_thread`; คิว GuildPlayback ไม่แตะ

**Round 2 — `.txt` attachment input:**
- เพิ่ม option `file` (`discord.Attachment`, optional); `text` → optional
- XOR guard ก่อน defer: ไม่มีทั้งคู่ → usage ephemeral; มีทั้งคู่ → "เลือก text หรือ file อย่างใดอย่างหนึ่ง" ephemeral
- `file` validation (ephemeral fail):
  - `.txt` เท่านั้น — `attachment.content_type` ขึ้นต้น `text/` **หรือ** `attachment.filename` ลงท้าย `.txt`
  - `attachment.size` ≤ 100 KB (เช็คก่อน download; 100KB/300 ≈ 340+ บรรทัด เกินพอ)
  - `await attachment.read()` → `.decode("utf-8")` strict; `UnicodeDecodeError` → "ไฟล์ต้องเป็น UTF-8 text"
- decode แล้วเข้าท่อเดิม: `parse_lines(decoded)` → `extract_mood` loop → `first_line_over_limit` → `resolve_instruct` loop → per-line 300 limit เหมือน `text` path เป๊ะ
- `mood:` dropdown override emoji เหมือนเดิม ไม่ว่า input มาจาก `text` หรือ `file`
- ลำดับ ack: type/size เช็คได้ก่อน `defer` (ไม่ต้อง download); decode+parse+limit เช็คหลัง `defer` → error ผ่าน `followup.send(ephemeral=True)`
- ไม่เพิ่ม intent (attachment มากับ interaction payload), ไม่เพิ่ม env var, ไม่เพิ่ม dependency

### Acceptance Criteria
- [ ] `/say text:<ข้อความ> [mood:<preset>]` ทำงาน: เข้า VC ของผู้สั่ง เล่นเสียง Liino เรียงคิวเหมือนเดิม
- [ ] `/say file:<x.txt>` ทำงาน: หลายบรรทัดในไฟล์ + auto mood จาก emoji ต่อบรรทัด เหมือน `text` path
- [ ] XOR: ไม่ระบุ `text`/`file` เลย → usage ephemeral; ระบุทั้งคู่ → error ephemeral
- [ ] `file` ที่ไม่ใช่ `.txt` / เกิน 100 KB / ไม่ใช่ UTF-8 → reject ephemeral, ไม่มีอะไรเข้าคิว
- [ ] ลิมิต MAX_CHARS ต่อบรรทัด reject ทั้ง batch พร้อมเลขบรรทัด (ephemeral) — ทั้ง `text` และ `file` path
- [ ] mood ผิด reject (ephemeral) — หรือถ้าใช้ choices จะเลือกผิดไม่ได้ตั้งแต่ต้น
- [ ] daemon ล่ม → error ephemeral ไม่ fallback โหลดโมเดลเอง (Decision TTS-1001 คงเดิม)
- [ ] ไม่มี `?say` เหลืออยู่ในโค้ด; Message Content Intent ไม่ถูกใช้อีก
- [ ] Ephemeral: usage/error เห็นเฉพาะคนสั่ง; success แจ้ง channel ปกติ

### Validation
- รันบอทจริง (`set -a; source .env; set +a; .venv/bin/python discord_say_bot.py`) ต้องมี log การ guild-sync command
- ทดสอบ `/say` จริงใน Discord:
  - `text:` — ปกติ, emoji mood, บรรทัดเกิน MAX_CHARS, daemon ล่ม
  - `file:` — .txt หลายบรรทัด (มีบรรทัดนำ emoji), .txt ที่มีบรรทัด 301+ ตัว (reject + เลขบรรทัด), ไฟล์ .png/.pdf (reject), ไฟล์ > 100 KB (reject), ไฟล์ latin-1/non-utf8 (reject)
  - XOR — ไม่ใส่อะไรเลย, ใส่ทั้ง text และ file
- ตรวจว่า `?say` ไม่ตอบสนองแล้ว

**Planned changes — `discord_say_bot.py`:**
1. `say` signature: `async def say(interaction, text: str | None = None, mood: str | None = None, file: discord.Attachment | None = None)`
2. `@app_commands.describe(...)` เพิ่ม `file="ไฟล์ .txt สำหรับข้อความหลายบรรทัด (1 บรรทัด = 1 ประโยค)"`; แก้ `text` describe เป็น "ข้อความบรรทัดเดียว (หลายบรรทัดให้ใช้ file:)"
3. เพิ่มบล็อกต้น handler (ก่อน `parse_lines`):
   ```python
   if (text is None) == (file is None):
       await interaction.response.send_message(
           "ใช้: /say text:<ข้อความ>  หรือ  /say file:<x.txt>  (อย่างใดอย่างหนึ่ง)",
           ephemeral=True); return
   if file is not None:
       name_ok = file.filename.lower().endswith(".txt")
       type_ok = (file.content_type or "").startswith("text/")
       if not (name_ok or type_ok):
           await interaction.response.send_message("ไฟล์ต้องเป็น .txt", ephemeral=True); return
       if file.size > 100_000:
           await interaction.response.send_message("ไฟล์ใหญ่เกิน 100 KB", ephemeral=True); return
   ```
4. หลัง `defer` (ตอนนี้ต้อง defer เร็วขึ้นถ้ามาจาก file — ย้าย logic): จริง ๆ ให้ decode ก่อน parse:
   - ถ้า `file`: `raw = await file.read()`; `try: source_text = raw.decode("utf-8") except UnicodeDecodeError:` → ephemeral (ถ้ายังไม่ defer ใช้ `response.send_message`; ออกแบบให้ decode อยู่ก่อน defer ได้เพราะ `file.read()` เร็วสำหรับ ≤100KB)
   - ถ้า `text`: `source_text = text`
   - `lines = parse_lines(source_text)` — ที่เหลือเหมือนเดิมทุกบรรทัด
   > decision: ทำ `file.read()` + decode **ก่อน** `defer` (ไฟล์ ≤100KB, download เร็ว); validation error ยังเป็น `response.send_message` ทั้งหมด สอดคล้อง pattern เดิม
5. success log: เพิ่ม `src=text|file` ใน stderr print (debug ว่ามาจากไหน)
6. usage message ใน `if not lines`: อัปเดตให้พูดถึงทั้ง `text:` และ `file:`

**Risks / decisions:**
- `file.read()` ก่อน `defer`: ไฟล์ ≤100 KB จาก Discord CDN โหลด <1s ปกติ → ทัน 3s ack; ถ้า CDN ช้า → interaction fail (Discord แสดง "application did not respond"). ยอมรับได้ที่ 100KB cap; ถ้า live test เจอ timeout → ย้าย `read()` ไปหลัง `defer` แล้ว decode error เป็น `followup`
- content_type ของ Discord สำหรับ .txt อาจเป็น `None` → fallback ที่ `.filename` endswith `.txt` (มี OR แล้ว)
- `.txt` ที่มี BOM (`﻿`): `utf-8` decode จะเหลือ BOM ที่ต้นบรรทัดแรก → `parse_lines` strip() ไม่ตัด BOM. ใช้ `decode("utf-8-sig")` แทนเพื่อกิน BOM
- attachment เป็น untrusted input แต่ปลายทางแค่ decode → text → `_try_daemon` (daemon reject >300/req อยู่แล้ว) → wav path ที่บอทตั้งเอง; ไม่มี eval/path traversal. security-review = light
- ไม่กระทบ Hermes / `qwen_clone_tts.py` CLI — บอทเท่านั้น
