## 🟢 TTS-1004: เปลี่ยน ?say prefix command เป็น slash command /say

Status: Plan
Priority: High

### Summary
ย้ายคำสั่ง say ของ Discord say-bot จาก prefix command `?say` (message-based) ไปเป็น application slash command `/say` ลบ `?say` ออกทั้งหมด — ใช้ slash อย่างเดียว

### Context
- ไฟล์หลัก: `discord_say_bot.py` ปัจจุบันใช้ `commands.Bot` + `@bot.command(name="say")` (TTS-1001)
- ต้องเปิด privileged "Message Content Intent" ใน Developer Portal เพราะ prefix command ต้องอ่านข้อความ — พอเปลี่ยนเป็น slash command แล้วจะไม่จำเป็นต้องใช้ intent นี้อีก (ลด dependency กับ portal setting)
- Behavior ปัจจุบันที่ต้องคงไว้ (TTS-1002/TTS-1003): รับหลายบรรทัด (array of lines), auto mood จาก emoji, `--mood <preset>`, ลิมิต MAX_CHARS ต่อบรรทัด, คิวเล่นเสียงต่อ guild, SAY_SENTENCE_GAP_S, VC idle timeout

### Decisions (ผู้ใช้ยืนยันแล้ว)
1. **ลบ ?say ทิ้ง** — ใช้ /say อย่างเดียว ไม่มี transition period
2. **Ephemeral reply สำหรับ error/usage** (มองเห็นเฉพาะคนสั่ง) — success แจ้งใน channel ปกติ

### Scope
- Refactor `discord_say_bot.py`:
  - เปลี่ยนจาก `commands.Bot` เป็น `discord.Client` (หรือ `commands.Bot` ที่ไม่ใช้ prefix) + register slash command ผ่าน `discord.app_commands` (`@app_commands.command(name="say")` / `Tree`)
  - Slash command option: `text` (string, จำเป็น), `mood` (optional choice จาก `MOOD_PRESETS` — ได้ autocomplete/choice dropdown ฟรี แทน `--mood` flag)
  - Sync command tree ตอน on_ready (guild-specific sync จะเห็นทันที ไม่ต้องรอ global propagation สูงสุด 1 ชม.)
  - ลบ `_parse_say_args` (regex `--mood`) เพราะ option parser ของ slash จัดการให้
  - ลบ `intents.message_content` และ docstring ส่วน prefix/Message Content Intent
- รองรับหลายบรรทัดใน slash option: slash command option เป็น single string อยู่แล้ว — newline ใน option คงทำงานได้ผ่าน parse_lines เดิม
- Ephemeral: error/usage → `interaction.response.send_message(..., ephemeral=True)`; success → แจ้ง channel ปกติ
- คง reuse เดิมจาก `qwen_clone_tts.py` (MAX_CHARS, MOOD_PRESETS, _try_daemon, resolve_instruct) และ `say_moods.py`; TTS ผ่าน `asyncio.to_thread`; คิว GuildPlayback ไม่แตะ

### Acceptance Criteria
- [ ] `/say text:<ข้อความ> [mood:<preset>]` ทำงาน: เข้า VC ของผู้สั่ง เล่นเสียง Liino เรียงคิวเหมือนเดิม
- [ ] หลายบรรทัด + auto mood จาก emoji ทำงานเหมือนเดิม (newline ใน option)
- [ ] ลิมิต MAX_CHARS ต่อบรรทัด reject ทั้ง batch พร้อมเลขบรรทัด (ephemeral)
- [ ] mood ผิด reject (ephemeral) — หรือถ้าใช้ choices จะเลือกผิดไม่ได้ตั้งแต่ต้น
- [ ] daemon ล่ม → error ephemeral ไม่ fallback โหลดโมเดลเอง (Decision TTS-1001 คงเดิม)
- [ ] ไม่มี `?say` เหลืออยู่ในโค้ด; Message Content Intent ไม่ถูกใช้อีก
- [ ] Ephemeral: usage/error เห็นเฉพาะคนสั่ง; success แจ้ง channel ปกติ

**Planned changes — `discord_say_bot.py`:**
1. เขียน module docstring ใหม่: slash `/say`, ตัดย่อหน้า Message Content Intent, ลบ `DISCORD_COMMAND_PREFIX`, เพิ่ม `DISCORD_GUILD_ID` (optional)
2. Imports: เพิ่ม `from discord import app_commands`; ลบ `import re`
3. ลบ `intents.message_content = True` — เหลือ `discord.Intents.default()` เฉย ๆ (ยังมี `voice_states` ที่ต้องใช้อ่าน `interaction.user.voice`)
4. แทน `bot = commands.Bot(...)` ด้วย:
   ```python
   client = discord.Client(intents=intents)
   tree = app_commands.CommandTree(client)
   ```
5. ลบ `COMMAND_PREFIX`, `_MOOD_ARG_RE`, `_parse_say_args`
6. เพิ่ม `DISCORD_GUILD_ID = os.environ.get("DISCORD_GUILD_ID")`
7. `on_ready` sync tree:
   ```python
   @client.event
   async def on_ready() -> None:
       if DISCORD_GUILD_ID:
           g = discord.Object(id=int(DISCORD_GUILD_ID))
           tree.copy_global_to(guild=g)
           synced = await tree.sync(guild=g)
       else:
           synced = await tree.sync()
       print(f"discord_say_bot: logged in as {client.user} "
             f"(slash cmds synced={len(synced)}, "
             f"guild={DISCORD_GUILD_ID or 'global'}, "
             f"idle_timeout={VC_IDLE_TIMEOUT_S:.0f}s)", file=sys.stderr, flush=True)
   ```
8. แทน handler `@bot.command(name="say")` ด้วย `@tree.command(...)`:
   - decorators: `@tree.command(name="say", description="...")`, `@app_commands.guild_only()`,
     `@app_commands.describe(text=..., mood=...)`,
     `@app_commands.choices(mood=[app_commands.Choice(name=m, value=m) for m in sorted(MOOD_PRESETS)])`
   - signature: `async def say(interaction: discord.Interaction, text: str, mood: app_commands.Choice[str] | None = None)`
   - `explicit_mood = mood.value if mood is not None else None`
   - logic ต่อจากนี้ยกมาจากเดิมทั้งหมด (parse_lines → extract_mood loop → first_line_over_limit → resolve_instruct loop → voice-channel check) เปลี่ยนแค่:
     - `ctx.reply(...)` ของ error/usage → `await interaction.response.send_message(..., ephemeral=True)` + `return` (ทุกจุดนี้อยู่ก่อน defer, ทำได้)
     - `ctx.author` → `interaction.user`; `ctx.guild` → `interaction.guild`; `ctx.channel` → `interaction.channel`
   - หลังผ่าน validation ทั้งหมด: `await interaction.response.defer(ephemeral=True)` (spinner เห็นเฉพาะคนสั่ง)
   - generate loop เดิม; daemon fail → `await interaction.followup.send("⚠️ TTS daemon ...", ephemeral=True)` + `return` (atomic cleanup เดิม)
   - success: `await interaction.channel.send(f"🔊 เข้าคิวแล้ว {len(wav_paths)} บรรทัด")` (public) แล้ว `await interaction.followup.send("✅ เข้าคิวแล้ว", ephemeral=True)` (เคลียร์ spinner); print stderr log เดิม (`ctx.guild.id` → `interaction.guild.id`)
9. `main()`: `bot.run(...)` → `client.run(...)`; คง token guard เดิม
