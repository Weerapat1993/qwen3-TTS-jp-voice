## 🟢 TTS-1010: `/say voice:` parameter + `resolve_instruct()` voice-default

Status: Backlog
Priority: Medium
Source: แยกจาก TTS-1009 (brainstorming gate) — TTS-1009 ทำ `/voice-clone` CRUD เสร็จแล้ว ส่วนที่แตะ `/say` + shared constant module มา ticket นี้เพื่อแยก regression risk

### Summary
หลัง TTS-1009 ผู้ใช้ clone เสียงใหม่จาก Discord ได้แล้ว แต่ `/say` ยังล็อกเสียง Liino (`_try_daemon(..., DEFAULT_VOICE, ...)`). ticket นี้:

- เพิ่ม optional `voice:` choice/autocomplete ให้ `/say` (สแกน `voices/*.wav`), default = Liino เมื่อไม่ระบุ (regression-safe)
- `resolve_instruct()` ใน `qwen_clone_tts.py` รับ voice-default: ลำดับ `mood > voice instruction (<Name>.instruct.txt) > default`

### Context
- **ต้องทำหลัง TTS-1009 merge** (พึ่ง `voice_store.py`: `list_voices`, `read_instruction`, `sanitize_name`)
- `qwen_clone_tts.py:103` `resolve_instruct(mood, instruct, instruct_long)` ตอนนี้ fallback `MOOD_PRESETS["default"]` เสมอ — เป็น single source of truth ตาม `CLAUDE.md`, ทั้ง `discord_say_bot.py` และ (indirect) daemon path พึ่ง
- `discord_say_bot.py:296` — `/say` loop เรียก `_try_daemon(spoken, wav_path, instruct, DEFAULT_VOICE, "wav", lang)` ต่อบรรทัด; `instruct` มาจาก `resolve_instruct(m, None, False)` ที่ line ~272
- daemon `_cache_key()` มี `voice` อยู่แล้ว → cache แยกต่อเสียงถูกต้อง; `handle_request()` อ่าน `voices/<voice>.wav`+`.txt` ได้เลย — **ไม่ต้องแก้ daemon**
- Hermes `--stdin` mode hardcode `--voice Liino` (`README_HERMES.md`) — ต้องไม่กระทบ; `resolve_instruct()` signature เปลี่ยนแบบ backward-compatible (param ใหม่ default `None`)

### Scope
- `qwen_clone_tts.py` — `resolve_instruct(mood, instruct, instruct_long, voice_default: str | None = None)`; ลำดับ: `instruct_long` > `mood` > `instruct` > `voice_default` > `MOOD_PRESETS["default"]`
  - _(decision ตอน plan: `instruct` explicit ควรชนะ `voice_default` หรือกลับกัน — ยืนยันกับผู้ใช้)_
- `discord_say_bot.py` `/say` — เพิ่ม `voice:` param (choice จาก `voice_store.list_voices()` หรือ autocomplete ถ้าเกิน 25 เสียง), sanitize, default Liino; อ่าน `voice_store.read_instruction(voice)` แล้วส่งเป็น `voice_default` เข้า `resolve_instruct()`; ส่ง `voice` เข้า `_try_daemon()`
- CLI `qwen_clone_tts.py` main — pass `voice_default` จาก `<voice>.instruct.txt` เมื่อมี (ให้ CLI กับ bot behave ตรงกัน)
- docs — README § Discord Bot (`/say voice:`), § CLI Reference

### Non-goals
- `/voice-clone` CRUD (อยู่ใน TTS-1009 แล้ว)
- Hermes `--stdin` เปลี่ยนเสียง (ยัง Liino) — เพิ่ม `Liino.instruct.txt` ภายหลังถ้าต้องการ
- long-text chunking, daemon protocol change

### Acceptance Criteria
- [ ] `/say voice:<ชื่อใหม่> text:"..."` → ออกเสียงด้วยเสียงใหม่ผ่าน daemon fast path
- [ ] `/say text:"..."` (ไม่ใส่ voice) → Liino เหมือนเดิม, byte-identical behavior (regression)
- [ ] ลำดับ instruct `mood > voice instruction > default` — unit test `resolve_instruct()` signature ใหม่ ครอบทุก branch
- [ ] `/voice-clone edit instruction:` แล้ว `/say voice:` ใช้ค่าใหม่ทันที (อ่าน `.instruct.txt` ตอน generate)
- [ ] `resolve_instruct()` เดิมเรียกแบบ 3 args ยังทำงาน (Hermes/CLI ไม่พัง)
- [ ] `voice:` ที่ไม่มีจริง / ชื่อแปลก → ephemeral error, ไม่ crash
- [ ] `.venv/bin/python -m pytest -q` เขียว

### Validation
- pytest: `resolve_instruct()` ลำดับใหม่ทุก branch (`test_qwen_clone_tts.py`), `/say` voice sanitize
- Manual Discord: `/say voice:` เสียงใหม่ + `/say` ปกติ + `/transcribe` regression
- `security-review` gate: `voice` field เข้า daemon จาก user input
