## 🎙️ TTS-1009: Discord slash command `/voice-clone` (create/list/edit/delete/test)

Status: Review
Priority: Medium
Source: คำขอผู้ใช้ (Wyitz) ใน Discord — อยาก clone เสียงใหม่จาก Discord โดยอัปโหลด mp3/wav, ถอดเสียงอัตโนมัติ (reuse feature transcribe), กำหนด Voice Instruction ของตัวละครเอง และแก้ไขภายหลัง

### Summary
ปัจจุบันการเพิ่มเสียงใหม่ต้อง copy ไฟล์เข้า `voices/` + เขียน transcript เองแบบ manual อยากได้ flow ครบวงจรบน Discord:

```
/voice-clone create  name:<ชื่อ> file:<.mp3/.wav/.m4a/.ogg> [instruction:<บรรยายน้ำเสียง>] [overwrite:<bool>]
/voice-clone list
/voice-clone edit    name:<ชื่อ> [instruction:<ข้อความใหม่>] [rename:<ชื่อใหม่>]
/voice-clone delete  name:<ชื่อ> confirm:<true>
/voice-clone test    name:<ชื่อ> [text:<ข้อความทดสอบ>] [mood:<preset>]
```

**Scope split (Decision):** optional `voice:` parameter ของ `/say` + `resolve_instruct()` voice-default refactor แยกไปเป็น **TTS-1010** — ticket นี้ทำ `/voice-clone` CRUD ล้วน

### Context
- `voices/Liino.wav` + `voices/Liino.txt` เป็น default voice — reserved (`liino`), ห้ามลบ/rename, create ทับต้อง `overwrite:true`
- `/transcribe` (TTS-1005) มี Whisper STT ผ่าน `stt_transcribe.py` (`transcribe as run_stt`, `probe_duration`) — `discord_say_bot.py` import อยู่แล้ว, reuse ได้เลยสำหรับถอดเสียงอ้างอิง → `voices/<Name>.txt`
- Voice Instruction เก็บเป็น `voices/<Name>.instruct.txt` (สั้น, English, "trait, trait, pacing" แนว `MOOD_PRESETS`)
- `tts_daemon.py` รองรับ `voice ≠ Liino` อยู่แล้ว: `handle_request()` อ่าน `voices/<voice>.wav` + `.txt`, `_cache_key()` มี `voice` — **ticket นี้ไม่แตะ daemon และไม่แตะ `qwen_clone_tts.py`**
- `test` ใช้ `_try_daemon(text, wav, instruct, voice=<name>, ...)` fast path ตรง ๆ

### Decisions (จาก brainstorming gate)
- **แยกเป็น 2 ticket:** TTS-1009 = `/voice-clone` CRUD; TTS-1010 = `/say voice:` param + `resolve_instruct()` voice-default (แยก regression risk ของ `/say` ออกจาก file-management)
- **`edit` มี `rename`:** ย้าย `.wav`/`.txt`/`.instruct.txt` ครบ, กันชื่อซ้ำ + reserved
- **permission:** ทุกคนใน guild ใช้ได้ (ไม่ gate — ตาม non-goals เดิม); role gating ภายหลังถ้าต้องการ
- **ref audio prep:** ffmpeg → mono 24kHz `pcm_s16le`, ตัดต้นคลิป 12 วิ; คลิปสั้นกว่า 3 วิ → reject (ไม่ใช้ `silenceremove` — filter เสี่ยงตัดคำ)
- โมดูลใหม่ `voice_store.py` (pure, ไม่ import discord) เป็น single source of truth ของ voice-file CRUD + sanitize → unit-test แยกจากบอทได้

### Implementation Plan

แผนละเอียด bite-sized (10 tasks) อยู่ใน `docs/superpowers/plans/2026-08-30-tts-1009-voice-clone-discord.md` สรุป:

- **Context to verify:**
  - `discord_say_bot.py` import `transcribe as run_stt`, `probe_duration`, `_try_daemon`, `MOOD_PRESETS`, `MAX_CHARS` อยู่แล้ว
  - `tts_daemon.py:301` ประกอบ `ref_audio` จาก `voices/<voice>.wav` — voice≠Liino ทำงานผ่าน daemon ได้เลย
  - test pattern: `test_<module>.py` ที่ repo root, ffmpeg-dependent test ใช้ `pytest.mark.skipif` (ดู `test_stt_transcribe.py`)
- **Planned changes:**
  1. `voice_store.py` (ใหม่): `sanitize_name` (`^[a-z0-9_]{1,32}$`), `RESERVED={"liino"}`, `voice_paths`, `voice_exists`, `read/write_instruction`, `list_voices`, `rename_voice`, `delete_voice`, `prepare_ref_audio` (ffmpeg mono/24k/trim + min-duration guard), `VoiceStoreError`
  2. `discord_say_bot.py`: `app_commands.Group("voice-clone")` + 5 subcommand (create/list/edit/delete/test) — pre-defer validation แบบ ephemeral, `asyncio.to_thread` สำหรับ ffmpeg/STT/daemon, `finally: os.remove(temp)`
  3. `test_voice_store.py` (ใหม่): sanitize (valid/`../x`/space/emoji/empty/uppercase), reserved gate, `list_voices` (tmp dir), instruction round-trip, rename (ครบ/partial/ซ้ำ/reserved), delete (ครบ/reserved), `prepare_ref_audio` (reject <3s, output mono/24k/≤12s — `skipif` ไม่มี ffmpeg)
  4. `README.md` § Discord Bot + Features row; `CLAUDE.md` architecture (เพิ่ม `voice_store.py` เป็น importer ของ `VOICES_DIR`)
- **Files likely to change:** `voice_store.py`, `test_voice_store.py`, `discord_say_bot.py`, `README.md`, `CLAUDE.md`
- **Validation:**
  - `.venv/bin/python -m pytest -q` เขียว
  - `.venv/bin/python -c "import discord_say_bot"` exit 0 ทุก task ที่แตะบอท
  - Manual Discord: create (mp3 จริง) → list → test → test mood → edit instruction → edit rename → delete (confirm gate) → delete liino (reject) → create `../x` / `Liino` no-overwrite (reject)
  - Regression: `/say` เดิม (ไม่มี voice) + `/transcribe` ทำงานเหมือนเดิม
- **Risks / decisions:**
  - ไม่แตะ `qwen_clone_tts.py` / `tts_daemon.py` → ไม่มี module-boundary / daemon-protocol risk; `security-review` ยังควรทำเพราะประกอบ argv ffmpeg จากไฟล์ที่ user อัปโหลด + `test` ส่ง user text ผ่าน daemon (mitigation: `dst` มาจาก `sanitize_name` เท่านั้น, argv เป็น list, ไม่มี `shell=True`, `src` เป็น temp path ที่บอทตั้งเอง)
  - `/voice-clone test` resolve instruct แบบ inline (`mood > <name>.instruct.txt > default`) ไม่แตะ `resolve_instruct()` — signature refactor + unit test ของลำดับนี้ย้ายไป TTS-1010
  - Whisper โหลดครั้งแรก ~1.6GB (เหมือน `/transcribe` เดิม) — ไม่ใช่ dep/ค่าใหม่

### Non-goals
- optional `voice:` parameter ของ `/say` + `resolve_instruct()` voice-default → **TTS-1010**
- เปิด long-text chunking ที่ gate ปิดอยู่
- upload หลายคลิปต่อเสียงเดียว (concat)
- permission/role gating ของ slash command (ทุกคนใน guild ใช้ได้)
- แก้ daemon cache/queue logic หรือ `qwen_clone_tts.py`
