## 🟢 TTS-1011: Remove `MOOD_PRESETS["long"]` / `DEFAULT_INSTRUCT_LONG`

Status: Review
Priority: Low
Source: คำขอผู้ใช้ (2026-08-30) ระหว่างคุย TTS-1010 review — instruct-long (เดิมเป็น `--instruct-long` flag, ถูกถอดออกแล้วใน PR #11 `chore/remove-instruct-long`, เหลือแค่ `--mood long` เรียกอันเดิมได้) ตอนนี้ซ้ำซ้อนกับกลไก per-voice default instruction ที่ TTS-1010 เพิ่ม (`/voice-clone set-default` + `<voice>.instruct.txt`) — ผู้ใช้เสนอให้ลบ `MOOD_PRESETS["long"]`/`DEFAULT_INSTRUCT_LONG` ทิ้งไปเลย

### Summary
`DEFAULT_INSTRUCT_LONG` (เสียง "young Japanese anime game character" สไตล์เดิม) เดิมเข้าถึงผ่าน `--instruct-long` flag ตรง ๆ; ถูกถอด flag ออกแล้วใน PR #11 (คง `MOOD_PRESETS["long"]` ไว้เป็นทางเรียกสำรองผ่าน `--mood long` เพราะตอนนั้น TTS-1010 ยังไม่ merge — ไม่งั้นจะไม่มีทางเรียกเสียงสไตล์เดิมได้เลยชั่วคราว)

หลัง TTS-1010 merge แล้ว เสียงสไตล์นี้เก็บเป็น per-voice instruction ได้ตรง ๆ ผ่าน `/voice-clone set-default` + เขียน `<voice>.instruct.txt` แทน — ทำให้ `MOOD_PRESETS["long"]`/`DEFAULT_INSTRUCT_LONG` เป็น dead weight ใน `qwen_clone_tts.py`

### Context
- **ต้องทำหลัง TTS-1010 merge เข้า `main`** (พึ่ง `voice_store.read_instruction()` / `<voice>.instruct.txt` ที่ TTS-1010 เพิ่ม — ยังอยู่ PR #10, สถานะ Review)
- PR #11 (`chore/remove-instruct-long`, ไม่มี ticket ผูก — ad-hoc) ถอด `--instruct-long` CLI flag ออกแล้ว, เก็บ `MOOD_PRESETS["long"]` ไว้เป็น bridge
- `MOOD_PRESETS["long"]` / `DEFAULT_INSTRUCT_LONG` อยู่ใน `qwen_clone_tts.py` — single source of truth ตาม `CLAUDE.md`, มี importer (`tts_daemon.py`, `discord_say_bot.py` mood dropdown, `tune_voice.py`)
- ถ้า `Liino` (default voice ที่ ship มากับ repo) เคยพึ่ง mood `long` สำหรับ default character voice ต้อง migrate เนื้อหา `DEFAULT_INSTRUCT_LONG` ไปเป็น `voices/Liino.instruct.txt` ก่อนลบ ไม่งั้นเสียงสไตล์นี้หายไปเฉย ๆ

### Scope
- `qwen_clone_tts.py`: ลบ `DEFAULT_INSTRUCT_LONG` constant, ลบ `MOOD_PRESETS["long"]` entry, ลบ comment ที่อ้างถึง `--instruct-long`/`MOOD_PRESETS["long"]` ใน docstring ของ `resolve_instruct()`
- `qwen_clone_tts.py`: `--stdin` branch (ใน `main()`) เพิ่มการอ่าน `voice_default = read_instruction("Liino")` แล้วส่งเข้า `resolve_instruct(mood, None, voice_default)` — ให้ตรงกับ CLI branch ปกติที่ทำอยู่แล้ว (`resolve_instruct(args.mood, args.instruct, voice_default)`) แก้ asymmetry เดิมที่ `--stdin` ไม่เคยหยิบ `<voice>.instruct.txt` เลย
- **ไม่ migrate** เนื้อหา `DEFAULT_INSTRUCT_LONG` ไปที่ไฟล์ voice ใด ๆ (ดู `### Decisions`) — ลบทิ้งตรง ๆ
- `discord_say_bot.py`: mood dropdown (`sorted(MOOD_PRESETS)`) จะหาย `long` ออกไปเอง เมื่อลบจาก dict — เช็คแล้วไม่มี hardcode `"long"` อื่นในไฟล์นี้
- docs: README.md/`CLAUDE.md` — เช็คแล้วไม่มี reference ถึง `"long"`/`DEFAULT_INSTRUCT_LONG` โดยตรง ข้ามได้
- `test_qwen_clone_tts.py`: ลบ/แก้ test ที่ผูกกับ `MOOD_PRESETS["long"]`/`DEFAULT_INSTRUCT_LONG` (`test_resolve_instruct_mood_long_still_reachable` บรรทัด ~70 + comment บรรทัด ~43)

### Non-goals
- ไม่แตะ mood preset อื่น (`excited`, `sleepy`, ฯลฯ)
- ไม่แตะ daemon protocol

### Acceptance Criteria
- [x] TTS-1010 merge เข้า `main` แล้วก่อนเริ่มงานนี้ (hard blocker) — merged ผ่าน PR #10 (`a7a6c57`)
- [x] `MOOD_PRESETS["long"]` / `DEFAULT_INSTRUCT_LONG` ลบออกจาก `qwen_clone_tts.py`
- [x] `--stdin` branch ส่ง `voice_default` (จาก `Liino.instruct.txt` ถ้ามี) เข้า `resolve_instruct()` เหมือน CLI branch
- [x] `.venv/bin/python -m pytest -q` เขียว (test ที่อ้าง `MOOD_PRESETS["long"]`/`DEFAULT_INSTRUCT_LONG` ต้องอัปเดต/ลบตาม)
- [x] `/voice-clone list` / mood dropdown ไม่มี `long` เหลือค้าง

### Validation
- `.venv/bin/python -m pytest -q` หลังลบ constant/entry + แก้ test
- Manual CLI: `.venv/bin/python qwen_clone_tts.py --text "..." --out outputs/x.wav` (ไม่ระบุ mood/instruct) → ยังได้ default voice ปกติ (ไม่มี `Liino.instruct.txt` จริง ตอนนี้จึงตกไปที่ `MOOD_PRESETS["default"]` เหมือนเดิม)
- Manual CLI: `.venv/bin/python qwen_clone_tts.py --text "..." --stdin` เทียบ behavior เดิม/ใหม่ ว่ายัง generate ได้ปกติหลังแก้ asymmetry
- Manual Discord: mood dropdown ไม่มี `long` แล้ว

### Decisions
- **ไม่ migrate** เนื้อหา `DEFAULT_INSTRUCT_LONG` ไปที่ voice ไหนทั้งสิ้น — ผู้ใช้ยืนยันว่า `voices/liinonew.instruct.txt` มีเนื้อหาคล้ายกัน (refined version) อยู่แล้วสำหรับ voice `liinonew` เพียงพอ ไม่ต้องสร้าง `voices/Liino.instruct.txt` ใหม่ ยอมรับว่าเสียงสไตล์ `DEFAULT_INSTRUCT_LONG` เดิม (ผูกกับ voice `Liino` ตรง ๆ) หายไปจาก `Liino`
- **แก้ `--stdin` asymmetry ด้วย** — แม้ decision แรกคือไม่ migrate แต่ผู้ใช้ยืนยันให้แก้ `--stdin` branch ให้ส่ง `voice_default` เข้า `resolve_instruct()` เหมือน CLI branch (ตอนนี้ `--stdin` ไม่เคยหยิบ `<voice>.instruct.txt` เลย) เพื่อความสมมาตรของกลไก per-voice default instruction ที่ TTS-1010 เพิ่ม แม้ผลลัพธ์วันนี้จะยังไม่ต่างจากเดิม (เพราะไม่มี `Liino.instruct.txt`) แต่จะพร้อมใช้ทันทีถ้ามีคนสร้างไฟล์นี้ทีหลังผ่าน `/voice-clone set-default`

### Implementation Plan
Skill ที่ใช้: `using-superpowers` (เลือก skill), plan แบบ concise — งาน single-file (`qwen_clone_tts.py` เป็นหลัก) + test file, ไม่แตะ daemon protocol/module boundary ข้าม importer จริง จึงไม่เข้าเกณฑ์ `writing-plans`/`brainstorming` เต็มรูปแบบ (ใช้แค่เพื่อ resolve open question ผ่าน `AskUserQuestion` แทน)

Files ที่จะแก้:
1. `qwen_clone_tts.py`
   - ลบ `DEFAULT_INSTRUCT_LONG` (constant) และ `"long": DEFAULT_INSTRUCT_LONG,` ใน `MOOD_PRESETS`
   - อัปเดต docstring ของ `resolve_instruct()` (บรรทัด comment ที่อ้าง `instruct_long`/`--instruct-long`/`--mood long` bridge — ไม่ relevant แล้วหลังลบ)
   - ใน `main()` branch `--stdin`: เพิ่ม `from voice_store import read_instruction` (ยกมาจาก CLI branch หรือ import ซ้ำในจุดเดียวกันของฟังก์ชัน) แล้วเปลี่ยน `instruct = resolve_instruct(mood, None)` → `instruct = resolve_instruct(mood, None, read_instruction("Liino"))`
2. `test_qwen_clone_tts.py`
   - ลบ `test_resolve_instruct_mood_long_still_reachable` (บรรทัด ~70) และ comment อ้าง `MOOD_PRESETS["long"]` (บรรทัด ~43)
   - เช็ก test อื่นที่ parametrize ผ่าน `sorted(MOOD_PRESETS)` หรือ list mood ตรง ๆ ว่าไม่พังเพราะ `long` หายไป
3. `discord_say_bot.py` / `README.md` / `CLAUDE.md` — เช็คแล้วไม่มี reference ตรง ต้องอ่านซ้ำหลังแก้เพื่อ confirm ไม่มีอะไรพัง (ไม่คาดว่าต้องแก้ไฟล์เหล่านี้จริง)
