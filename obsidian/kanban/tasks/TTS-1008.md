## 🔴 TTS-1008: daemon fast path ล้มเหลว "no audio produced" เมื่อ out_path เป็น relative

Status: Review
Priority: Medium
Source: ข้อสังเกตนอก scope ระหว่าง review TTS-1007 (`obsidian/kanban/tasks/TTS-1007.md` § Review Notes) — daemon ตอบ `no audio produced` ทุก request, client fallback in-process

### Summary
`qwen_clone_tts.py` ที่รันจาก project dir ด้วย `--out outputs/x.wav` (relative path) ส่ง `out_path` ดิบ ๆ ไปให้ daemon ผ่าน socket. daemon ที่ launchd รันมี working directory = `/` (plist ไม่ตั้ง `WorkingDirectory`) → `mlx_audio.generate_audio()` เรียก `os.makedirs("outputs")` เทียบกับ `/` → `OSError: [Errno 30] Read-only file system: 'outputs'` → daemon ตอบ `{"ok": false, "error": "no audio produced — mlx output: ..."}` → client fallback ไปโหลดโมเดลเอง (ช้า ~3-10s ต่อ call) แต่ยังพิมพ์ `OK <path>` จึงดูเหมือนปกติ

Daemon fast path จึง **ใช้ไม่ได้เลย** สำหรับทุก call ที่ `out_path` เป็น relative — รวมงาน manual CLI / `tune_voice` / Hermes `--stdin` ถ้าส่ง path relative. Discord bot ไม่โดนเพราะส่ง absolute temp path (`/var/folders/...`) — cache hit / complete ใน telemetry เป็นของ bot

### Context
- `qwen_clone_tts.py:160` `_try_daemon()` — `sock.sendall(json.dumps({... "out_path": out_path ...}))` ส่ง `out_path` ที่ได้จาก CLI arg ตรง ๆ ไม่ผ่าน `os.path.abspath()`
- `tts_daemon.py:243` `handle_request()` — ใช้ `out_path` ที่รับมาตรง ๆ; `_generate()` (`tts_daemon.py:166`) ส่งต่อเป็น `output_path=out_path` ให้ `generate_audio()`
- `mlx_audio/tts/generate.py:206` — `os.makedirs(output_path, exist_ok=True)` (treat เป็น dir) → relative path resolve เทียบ cwd ของ daemon
- `launchd/com.liino.qwen-tts-daemon.plist` — ไม่มี `<key>WorkingDirectory</key>` → launchd default cwd = `/`
- telemetry `~/Library/Logs/qwen_tts_daemon.log` — 19 `event: error` ทั้งหมด `[Errno 30] Read-only file system: 'outputs'` (traceback ชี้ `generate.py:206`)
- daemon cache-hit path (`tts_daemon.py:~316`) ใช้ `os.makedirs(os.path.dirname(out_path) or ".")` — relative `out_path` ที่ไม่มี dir component จะได้ `"."` = `/` เช่นกัน (จะ fail ตอน copy) แต่ปัจจุบันไม่ trigger เพราะ requester เดียวที่ cache-hit คือ bot (absolute path)
- protocol hand-implement 2 ฝั่ง — แก้ต้องคง backward compatible (client เดิมที่ส่ง absolute อยู่แล้วต้องไม่พัง); ดู `CLAUDE.md` § Architecture + `README.md` § Protocol + `README_HERMES.md` (Hermes shell out `--stdin`)

### Repro
1. `.venv/bin/python tts_daemon.py` (หรือ launchd service รันอยู่) — socket `/tmp/qwen_tts_daemon.sock` มีอยู่
2. `cd` เข้า project dir, รัน `.venv/bin/python qwen_clone_tts.py --text "hello" --mood gentle --out outputs/repro.wav`
3. observed: stderr `ERROR: daemon failed: no audio produced — mlx output: ... OSError: [Errno 30] Read-only file system: 'outputs'` แล้วตามด้วย in-process fallback + `OK outputs/repro.wav` (ช้า)
4. expected: daemon สร้างไฟล์ได้เลย, `TIMING via daemon ...`

### Scope
- **`qwen_clone_tts.py` `_try_daemon()`:** แปลง `out_path` เป็น `os.path.abspath(out_path)` ก่อน `json.dumps` — client รู้ cwd ที่ผู้ใช้ตั้งใจ, daemon ไม่รู้
- **`tts_daemon.py` `handle_request()`:** guard — ถ้า `out_path` ไม่ใช่ absolute → ตอบ error ชัด ๆ (`out_path must be absolute`) แทนที่จะปล่อยให้ mlx โยน traceback งง ๆ; ทุกจุดที่ `os.makedirs(os.path.dirname(out_path) or ".")` ให้ปลอดภัยกับ absolute path (ยัง backward compatible)
- **`launchd/com.liino.qwen-tts-daemon.plist`:** เพิ่ม `<key>WorkingDirectory</key><string>/Users/mungmee/Desktop/Project/Python/qwen3-tts-apple-silicon</string>` เป็น defense-in-depth (relative path ที่หลุดมาจะ resolve เข้า project แทน `/`)
- **docs:** `README.md` § Daemon `Protocol` ระบุว่า `out_path` ต้อง/จะถูกทำให้เป็น absolute; note ใน `README_HERMES.md` ถ้าจำเป็น
