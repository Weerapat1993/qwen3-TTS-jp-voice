## 🟢 TTS-1007: เพิ่ม mood presets ใหม่ (งอน/เขิน/ภูมิใจ/กังวล) + A/B validate ว่าโมเดลแยกเสียงจริง

Status: Todo
Priority: Medium
Source: feedback ผู้ใช้ 2026-08-30 (ต่อจาก TTS-1006 — ใส่ emoji mood ต่อบรรทัดให้บทสนทนาตัวละคร แล้วพบว่าคลัง mood หยาบเกินไป)

### Summary
คลัง mood ปัจจุบันมี 10 ตัว (`excited, giggle, surprised, sad, angry, sleepy, whisper, gentle, bored, storyteller`) — ไม่ครอบโทนที่บทสนทนาตัวละครต้องการบ่อย เช่น "งอน/บูด" (ตอนนี้ต้องฝืนใช้ `angry`), "เขิน", "ภูมิใจ", "กังวล". งานนี้เพิ่ม mood preset ใหม่เข้า 3 จุดที่ผูกกัน (`MOOD_PRESETS` ใน `qwen_clone_tts.py`, `EMOJI_MOOD`/`MOOD_EMOJI` ใน `say_moods.py`, `MOOD_KEYWORDS` ใน `transcribe_mood.py`) + README emoji map. **Task แรกคือ A/B validate ด้วย `tune_voice.py`** ว่า Qwen3-TTS-12Hz ออกเสียงแยก mood ใหม่ได้ยินจริง — ถ้าโมเดลแยกไม่ออก บันทึกผลแล้วหยุด/close ไม่เพิ่ม preset ลม ๆ

### Context
- `MOOD_PRESETS: dict[str, str]` ใน `qwen_clone_tts.py` (~บรรทัด 40-70) — instruct เป็น English "trait, trait, pacing" style; `resolve_instruct()` เป็น single source ให้ CLI + daemon + discord
- `say_moods.py`:
  - `EMOJI_MOOD: dict[str,str]` — emoji codepoint เดี่ยว → mood name (comment ระบุ: ไม่มี ZWJ sequence, `extract_mood` iterate ทีละ char)
  - `MOOD_EMOJI: dict[str,str]` — mood name → emoji ตัวแทน 1 ตัว (ใช้ตอน `/transcribe` เติม prefix); `default`/`long` จงใจไม่มี emoji
- `transcribe_mood.py`: `MOOD_KEYWORDS` — keyword ไทย/อังกฤษ/ญี่ปุ่น → mood; entry แรกที่ substring match ชนะ; `detect_mood()` คืนชื่อ mood ที่ `MOOD_EMOJI` รู้จักเสมอ
- `discord_say_bot.py`: `/say mood:` choices = `sorted(MOOD_PRESETS)` — เพิ่ม preset แล้วขึ้น dropdown เอง ไม่ต้องแก้
- README.md: §Discord Bot "Emoji → mood map" table (~บรรทัด 269-283), §Discord Bot `mood:` bullet (265), §Feature table (29)
- `tune_voice.py` = ad-hoc A/B script (ไม่ใช่ test) → generate sample ข้าม instruct variant เข้า `outputs/tuning/<run_id>/` พร้อม `results.md`
- โมเดลไม่รองรับภาษาไทยใน `codec_language_id` (จาก TTS-1006) — mood/instruct แยกจาก `lang_code` ส่งคู่กันได้ ไทยยังใช้ `auto`

### Scope
- **Task 1 — A/B validate (gate):** ร่าง instruct string สำหรับ mood ใหม่ + generate sample ด้วย `tune_voice.py` เทียบกับ mood ใกล้เคียงที่มี (`angry`, `gentle`, `excited`) → ฟัง → บันทึกผลใน `### Validation Results` ของ ticket นี้ (อ้าง `results.md`). ถ้าโมเดลแยกเสียงไม่ได้ → หยุด ทำ `### Open Questions` / เสนอ close
- **Task 2 — `qwen_clone_tts.py`:** เพิ่ม mood ใหม่เข้า `MOOD_PRESETS` — instruct English, style "trait, trait, pacing" สั้น ตรงตาม convention (CLAUDE.md)
- **Task 3 — `say_moods.py`:** เพิ่ม `MOOD_EMOJI[<new>]` + `EMOJI_MOOD` (emoji codepoint เดี่ยว ห้าม ZWJ; ห้ามชน emoji เดิม); guard round-trip
- **Task 4 — `transcribe_mood.py`:** เพิ่ม entry ใน `MOOD_KEYWORDS` (ไทย/อังกฤษ/ญี่ปุ่น) สำหรับ mood ใหม่ — วางลำดับความสำคัญให้ไม่แย่งเคสของ mood เดิม
- **Task 5 — docs/test:** README.md emoji map table + preset ตัวอย่าง; อัปเดต/เพิ่ม test ใน `test_say_moods.py` / `test_transcribe_mood.py` (ถ้ามี) — round-trip emoji, detect_mood keyword ใหม่

### Non-goals
- ยกระดับ `/transcribe` auto-mood จาก keyword heuristic เป็น per-line sentiment/LLM (แยก ticket)
- รองรับ ZWJ / multi-codepoint emoji ใน `extract_mood`
- ภาษาต่อบรรทัดใน `/say file:`
- แตะ voice-clone ref audio, `lang_code` path, daemon protocol
- เพิ่ม mood ที่โมเดลออกเสียงไม่ต่างจากตัวที่มี (ต้องผ่าน Task 1)

### Acceptance Criteria
- [ ] Task 1: `tune_voice.py` A/B run มีผลบันทึกใน ticket (`### Validation Results` + path `outputs/tuning/<run_id>/results.md`) — ระบุชัดว่าโมเดลแยกเสียง mood ใหม่แต่ละตัวได้ยิน "ต่างจาก" mood ที่ใกล้ที่สุด หรือไม่
- [ ] `MOOD_PRESETS` มี mood ใหม่ ≥ 1 ตัวที่ผ่าน Task 1 (target: งอน/เขิน/ภูมิใจ/กังวล เท่าที่ผ่าน) — instruct English, "trait, trait, pacing" style
- [ ] ทุก mood ใหม่มีทั้ง `MOOD_EMOJI[m]` และ key ใน `EMOJI_MOOD` ที่ map กลับเป็น `m`; `extract_mood(MOOD_EMOJI[m] + " ข้อความ") == ("ข้อความ", m)`
- [ ] emoji ที่เพิ่มเป็น codepoint เดี่ยว และไม่ชนกับ key เดิมใน `EMOJI_MOOD`
- [ ] `detect_mood()` คืน mood ใหม่เมื่อเจอ keyword ที่เพิ่ม (มี case ไทย + อังกฤษ + ญี่ปุ่นอย่างละ ≥1); mood เดิมไม่ regress
- [ ] `/say mood:<new>` ใช้งานได้ (dropdown ขึ้นอัตโนมัติจาก `sorted(MOOD_PRESETS)`)
- [ ] `.venv/bin/python -m pytest -q` เขียว
- [ ] README.md emoji map table + `mood:` bullet ตรงกับโค้ด

### Validation
- Task 1: `.venv/bin/python tune_voice.py` (ดู script args) → `outputs/tuning/<run_id>/results.md` → ฟังเทียบ mood ใหม่ vs `angry`/`gentle`/`excited`
- CLI: `.venv/bin/python qwen_clone_tts.py --text "ก็ได้ ตามใจ" --mood pouty --out outputs/pouty.wav` → `OK <path>` + ฟัง
- Unit: `.venv/bin/python -m pytest -q` เขียว (round-trip emoji + `detect_mood` keyword ใหม่)
- Regression: `detect_mood` เคสเดิมจาก TTS-1005 ยังคืน mood เดิม; `extract_mood` emoji เดิมยังทำงาน
- Discord live: `/say text:"..." mood:pouty`; ไฟล์ `.txt` ที่ขึ้นต้นบรรทัดด้วย emoji ใหม่ → พูดด้วย mood ที่ถูก
- Round-trip: `/transcribe` ข้อความที่มี keyword ใหม่ (เช่น "งอน") → เติม emoji ใหม่ → `/say file:` อ่านกลับเป็น mood เดิม

### Open Questions
1. **ชุด mood ที่จะเพิ่มแน่ ๆ** — เสนอ `pouty` (งอน/บูด), `shy` (เขิน), `proud` (ภูมิใจ), `worried` (กังวล). ยืนยัน/ตัด ตอน plan หลังเห็นผล Task 1
2. **emoji collision** — `angry` ใช้ `😠 😡 😤` แล้ว, `bored` ใช้ `😑 😐 🙄` แล้ว → `pouty` ต้องหา codepoint เดี่ยวที่ว่างและสื่อความหมาย (คั่นต้น: `😒` unamused, `😾` pouting cat?, `🥲`); `shy` → `😳` / `☺`; `proud` → `😌` / `😏`; `worried` → `😟` / `😧`. ยืนยันตอน plan
3. **`pouty` ทับ `angry` ไหม** — instruct ปัจจุบันของ `angry` คือ "Angry, pouty ... playful irritation, not genuinely hostile" ซึ่งกินโซน "งอน" อยู่แล้วบางส่วน → Task 1 ต้องพิสูจน์ว่า `pouty` แยกจาก `angry` ได้ยินจริง ไม่งั้นแค่ปรับ doc/emoji ของ `angry` ก็พอ
