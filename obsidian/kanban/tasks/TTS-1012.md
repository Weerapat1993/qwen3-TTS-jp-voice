## 🟢 TTS-1012: Inline mood tag (`[mood:xxx]`) support for `--stdin` batch text

Status: Done
Priority: Medium
Source: คำขอผู้ใช้ (2026-08-30) ระหว่างคุยเรื่องผลของ `--instruct`/`--mood` ต่อการออกเสียง — ผู้ใช้อยากใส่ emoji ใน instruct เพื่อคุมอารมณ์ต่อท่อนข้อความ แต่ `--stdin` ส่งไฟล์ `.txt` ก้อนเดียว ไม่มีทางแยก mood ต่อบรรทัดได้ และ emoji ดิบไม่ deterministic (ไม่ใช่ training distribution ของ `instruct` text) — ตกลงกันว่า inline mood tag ที่ map เข้า `MOOD_PRESETS` ที่มีอยู่แล้วเป็นทางที่ deterministic กว่า

### Summary
เพิ่มความสามารถให้ `--stdin` batch text แบ่ง mood ได้หลายท่อนในไฟล์เดียว ผ่าน tag รูปแบบ `[mood:xxx]` แทรกในเนื้อความ (`xxx` ต้องเป็นคีย์ใน `MOOD_PRESETS`) — เนื้อความหลัง tag จนถึง tag ถัดไป (หรือจบไฟล์) ใช้ mood นั้น ไฟล์ที่ไม่มี tag เลยทำงานเหมือนเดิมทุกอย่าง (fallback `--mood`/`--instruct`/per-voice default ปกติ)

Protocol daemon **ไม่ต้องแก้** — `tts_daemon.py handle_request()` (`tts_daemon.py:251`) รับ `instruct` ต่อ request อยู่แล้ว งานนี้เป็น client-side parsing ล้วนใน `qwen_clone_tts.py`

### Context
- `chunk_text()` (`qwen_clone_tts.py:115-143`) ปัจจุบันตัดข้อความยาวตาม `MAX_CHARS` (ขอบประโยค/ช่องว่าง) ล้วนๆ ไม่รู้จัก mood tag ต้องรัน tag-split **ก่อน** `chunk_text()` แล้วค่อยรัน `chunk_text()` แยกต่อ segment (segment ยาวเกิน `MAX_CHARS` ยังต้องถูกตัดต่อเหมือนเดิม)
- `--stdin` branch ใน `main()` เพิ่งถูกแก้ให้ส่ง `voice_default` (`read_instruction("Liino")`) เข้า `resolve_instruct()` ใน TTS-1011 ([[TTS-1011]]) — งานนี้ต้องรักษา wiring นั้นไว้ ให้ segment ที่ไม่มี tag ยัง fallback ไปตาม priority เดิม (mood > instruct > per-voice default > `MOOD_PRESETS["default"]`)
- `README_HERMES.md:40` ระบุ Hermes ส่งข้อความผ่านไฟล์ (`--stdin input.txt`) เป็น plain text ธรรมดา ไม่มีการใช้ `[...]` bracket syntax ใดๆ ในเอกสารตอนนี้ — ความเสี่ยง false-positive ต่ำ แต่ **ต้องยืนยันกับผู้ใช้ก่อนเริ่ม implement** ว่า Hermes เนื้อหาจริงจะไม่ชน pattern `[mood:xxx]` โดยบังเอิญ (ดู `### Open Questions`)
- multi-chunk generation path (`_run()`/`_generate()` ที่มี ffmpeg concat) มีอยู่แล้วสำหรับ text ยาวเกิน `MAX_CHARS` ปัจจุบัน — งานนี้ reuse concat mechanism เดิม ไม่สร้างใหม่ (แค่เพิ่มมิติ "segment ใช้ instruct ต่างกัน" เข้าไปใน loop เดิม)

### Scope
- `qwen_clone_tts.py`: เพิ่มฟังก์ชัน parse `[mood:xxx]` tag แยกข้อความเป็น `list[tuple[mood_key: str | None, text: str]]` (ก่อน tag แรก ถ้ามีเนื้อความ ให้ `mood_key=None` แล้ว fallback ตาม priority เดิม)
- `qwen_clone_tts.py`: `--stdin` branch ใน `main()` ใช้ parser ใหม่นี้แทนการ resolve instruct ตัวเดียวทั้งไฟล์ — วนแต่ละ segment → `chunk_text()` → `resolve_instruct(segment_mood, None, voice_default)` ต่อ chunk
- Validate mood key ที่ไม่รู้จักใน tag (typo) — ตัดสินใจ behavior ใน `### Decisions`/`### Open Questions` (fail ทั้งไฟล์ หรือ fallback เงียบๆ)
- ไม่แตะ CLI branch ปกติ (`--text`/`--instruct`/`--mood` ตรงๆ) — ยังเป็น instruct เดียวทั้งคำสั่งเหมือนเดิม
- ไม่แตะ `tts_daemon.py` protocol (ยืนยันแล้วว่าไม่จำเป็น)

### Non-goals
- ไม่ทำ mapping emoji→mood อัตโนมัติ (ผู้ใช้ยัง map เองเป็น tag)
- ไม่แตะ `discord_say_bot.py` mood dropdown ในงานนี้ (คนละ input path จาก `--stdin`)
- ไม่เปลี่ยน `MAX_CHARS` หรือ chunk-boundary logic เดิมของ `chunk_text()`
