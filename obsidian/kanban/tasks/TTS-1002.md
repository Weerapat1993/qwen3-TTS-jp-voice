## 🟢 TTS-1002: ?say รับข้อความหลายบรรทัด (array) + auto mood จาก emoji

Status: Plan
Priority: Medium
Ref: idea จาก Wyitz (2026-08-30, thread นี้)

### Summary
ต่อยอด `?say` จาก TTS-1001 ให้ (1) รับข้อความหลายบรรทัด — 1 บรรทัด = 1 ประโยค แล้ว generate + เล่นเรียงคิวตามลำดับ, (2) auto-detect mood จาก emoji ในแต่ละประโยค โดย map emoji → `MOOD_PRESETS` ที่มีอยู่

### Context
- TTS-1001 (`?say <ข้อความ> [--mood <preset>]`) เสร็จ DONE — playback queue ต่อ guild, idle-leave, reuse `MAX_CHARS`/`MOOD_PRESETS`/`resolve_instruct`/`_try_daemon` จาก `qwen_clone_tts.py`
- `_parse_say_args()` ใน `discord_say_bot.py` parse `--mood` อยู่แล้ว — emoji auto-detect เป็น layer ใหม่บนเส้นทางนี้
- daemon มี response cache ต่อ (voice, text, instruct) — ประโยคเดียวกันคนละ mood จะ cache แยกกันเอง ไม่ต้องแตะ daemon

### Scope
- `?say` รับ multi-line: แยกข้อความด้วย newline ได้ (1 บรรทัด = 1 ประโยค) — generate ทุกบรรทัดแล้วเล่นเรียงคิวตามลำดับบรรทัด
- Emoji auto-mood: ต่อ 1 ประโยค หา emoji ตัวแรกที่เจอ (เจอกี่ตัวก็ใช้ตัวแรก) แล้ว map เป็น mood preset
- Emoji ที่ใช้กำหนด mood จะถูก **ตัดออกจากข้อความที่พูด** (พูดเฉพาะตัวอักษร)
- `--mood <preset>` ที่พิมพ์เองชนะ emoji เสมอ (explicit > auto) — ตัดสินใจแล้วกับผู้ใช้ (2026-08-30)
- ผู้ใช้ตอบคำถาม design แล้ว: array = แยกบรรทัด, emoji ตัวแรกต่อประโยค, ตัด emoji ออกจากข้อความพูด

### Acceptance Criteria
- `?say` ด้วยข้อความ 2-3 บรรทัด → เล่นเรียงตามลำดับบรรทัด ไม่ทับกัน
- `?say 😄สวัสดี` → พูด "สวัสดี" ด้วย mood ตาม map ของ 😄, ตัด emoji ออก
- `?say --mood excited 😄สวัสดี` → ใช้ `--mood excited` เสมอ (ไม่สน emoji)
- บรรทัดที่ไม่มี emoji → ใช้ mood default
- บรรทัดว่าง/whitespace ล้วน → ข้าม
- ความยาวรวมของข้อความที่จะพูด (หลังตัด emoji) เกิน MAX_CHARS → reject ด้วย error ชัดเจน
- daemon ล่ม → error เหมือนเดิม ไม่ค้าง (policy เดียวกับ TTS-1001)

### Validation
- รันจริงใน Discord VC: multi-line, emoji auto-mood, `--mood` override emoji, บรรทัดว่าง, เกิน MAX_CHARS
- ตรวจ playback เรียงคิวตามลำดับ (ffmpeg exit 0 ทุกไฟล์, ไม่ซ้อน)
- ตรวจ emoji→mood mapping เป็น pure logic — พิจารณาเขียน unit test ตาม coding-style.md ตอน implement

```python
"""Pure logic สำหรับ ?say multi-line + emoji auto-mood (TTS-1002)

แยกจาก discord_say_bot.py เพื่อ unit test ได้ isolated — ไม่ import discord

# map เฉพาะ mood ที่มี emoji สื่อความหมายชัด — ไม่ map default/long
EMOJI_MOOD: dict[str, str] = {
    "😄": "excited", "😁": "excited", "😃": "excited", "🎉": "excited", "⚡": "excited",
    "😆": "giggle", "🤣": "giggle", "😂": "giggle", "😹": "giggle",
    "😮": "surprised", "😲": "surprised", "😯": "surprised", "😱": "surprised",
    "😢": "sad", "😭": "sad", "😔": "sad", "💔": "sad",
    "😠": "angry", "😡": "angry", "😤": "angry",
    "😴": "sleepy", "😪": "sleepy", "🥱": "sleepy",
    "🤫": "whisper", "🤐": "whisper",
    "🥺": "gentle", "🤗": "gentle", "💗": "gentle",
    "😑": "bored", "😐": "bored", "🙄": "bored",
    "📖": "storyteller", "📚": "storyteller", "🧚": "storyteller",
}


def parse_lines(raw: str) -> list[str]:
    """split ข้อความเป็นบรรทัด: 1 บรรทัด = 1 ประโยค

    strip แต่ละบรรทัด, ทิ้งบรรทัดที่ว่าง/whitespace-ล้วน, คงลำดับเดิม
    """
    out: list[str] = []
    for line in raw.split("\n"):
        s = line.strip()
        if s:
            out.append(s)
    return out
```

```python
def extract_mood(line: str) -> tuple[str, str | None]:
    """หา emoji ตัวแรกที่ map ได้ใน line -> คืน (ข้อความที่ตัด emoji นั้นออก, mood)

    - scan ทีละ character หา key แรกที่อยู่ใน EMOJI_MOOD (emoji ในตารางนี้เป็น
      codepoint เดี่ยวทั้งหมด ไม่มี ZWJ sequence จึง iterate ทีละ char พอ)
    - ตัด emoji ตัวนั้นออก 1 ครั้ง แล้ว strip ช่องว่างหัวท้าย
    - ไม่เจอ emoji ที่ map ได้ -> คืน (line.strip(), None); emoji อื่นไม่แตะ
    """
    for i, ch in enumerate(line):
        mood = EMOJI_MOOD.get(ch)
        if mood is not None:
            stripped = (line[:i] + line[i + 1:]).strip()
            return stripped, mood
    return line.strip(), None
```

```python
_MOOD_ARG_RE = re.compile(r"(?:^|\s)--mood\s+(\S+)")


def _parse_say_args(raw: str) -> tuple[str, str | None]:
    """แยก `--mood <preset>` ออกจาก raw เหลือแค่ข้อความที่จะพูด

    prefix command ธรรมดาไม่มี option parser ของ slash command จึงต้อง parse เอง

    mood: str | None = None
    m = _MOOD_ARG_RE.search(raw)
    if m:
        mood = m.group(1)
        raw = raw[:m.start()] + raw[m.end():]
    return raw.strip(), mood
```

```python
@bot.command(name="say")
@commands.guild_only()
async def say(ctx: commands.Context, *, text: str = "") -> None:
    raw, explicit_mood = _parse_say_args(text)
    lines = parse_lines(raw)
    if not lines:
        await ctx.reply(
            f"ใช้: `{COMMAND_PREFIX}say <ข้อความ>` (หลายบรรทัดได้ 1 บรรทัด = 1 ประโยค) "
            f"`[--mood <preset>]`\nmood: {', '.join(sorted(MOOD_PRESETS))}")
        return

    # (spoken_text, mood ที่จะใช้จริง) ต่อบรรทัด — explicit --mood ชนะ emoji เสมอ
    prepared: list[tuple[str, str | None]] = []
    for line in lines:
        spoken, auto_mood = extract_mood(line)
        if not spoken:
            continue  # บรรทัดที่เหลือแต่ emoji/ว่าง -> ข้าม
        prepared.append((spoken, explicit_mood or auto_mood))
    if not prepared:
        await ctx.reply("ไม่มีข้อความให้พูด (บรรทัดว่าง/มีแต่ emoji ทั้งหมด)")
        return

    total_chars = sum(len(spoken) for spoken, _ in prepared)
    if total_chars > MAX_CHARS:
        await ctx.reply(f"⚠️ ข้อความยาวเกินไป ({total_chars} ตัวอักษรรวมทุกบรรทัด "
                         f"หลังตัด emoji) — จำกัดไม่เกิน {MAX_CHARS} ตัวอักษร")
        return

    # resolve instruct ทุกบรรทัดก่อน (mood ผิด -> reject ทั้ง batch)
    jobs_meta: list[tuple[str, str | None]] = []  # (spoken, instruct)
    for spoken, mood in prepared:
        try:
            instruct = resolve_instruct(mood, None, False)
        except ValueError as e:
            await ctx.reply(f"⚠️ {e}")
            return
        jobs_meta.append((spoken, instruct))

    author_voice = getattr(ctx.author, "voice", None)
    if author_voice is None or author_voice.channel is None:
        await ctx.reply("ต้องเข้า voice channel ก่อนถึงจะใช้คำสั่งนี้ได้")
        return
    voice_channel = author_voice.channel

    # generate ครบทุกบรรทัดก่อน queue — บรรทัดใด fail -> ลบไฟล์ทั้ง batch, ไม่ queue
    t0 = time.time()
    wav_paths: list[str] = []
    for idx, (spoken, instruct) in enumerate(jobs_meta):
        wav_path = os.path.join(
            tempfile.gettempdir(),
            f"qwen_say_{os.getpid()}_{int(time.time()*1000)}_{idx}.wav")
        ok = await asyncio.to_thread(
            _try_daemon, spoken, wav_path, instruct, DEFAULT_VOICE, "wav")
        if not ok:
            for p in wav_paths:
                try:
                    os.remove(p)
                except OSError:
                    pass
            try:
                os.remove(wav_path)
            except OSError:
                pass
            # Decision (ดู TTS-1001 plan): daemon ล่ม/ตอบ error -> แจ้งทันที
            # ไม่ fallback ไปโหลดโมเดลเองในบอท; batch เป็น atomic
            await ctx.reply("⚠️ TTS daemon ไม่พร้อมใช้งาน (ล่ม/ยังไม่ได้รัน หรือสร้าง"
                             "เสียงไม่สำเร็จ) — ไม่มีบรรทัดไหนถูกเล่น ตรวจ log ของบอท "
                             "แล้วลองสตาร์ท `tts_daemon.py` ใหม่")
            return
        wav_paths.append(wav_path)
    gen_s = time.time() - t0

    playback = _get_playback(ctx.guild)
    playback.ensure_worker()
    for wav_path in wav_paths:
        await playback.queue.put((voice_channel, ctx.channel, wav_path))
    print(f"discord_say_bot: queued say guild={ctx.guild.id} "
          f"lines={len(wav_paths)} gen_s={gen_s:.2f} "
          f"explicit_mood={explicit_mood} chars={total_chars}",
          file=sys.stderr, flush=True)
```

#### Risks / decisions

- **`_parse_say_args` regex vs `.split()`**: เปลี่ยนวิธี parse `--mood` — regex `(?:^|\s)--mood\s+(\S+)` จับ match แรก ถ้าผู้ใช้พิมพ์ `--mood` ในเนื้อความจริง ๆ จะถูกตัด (เหมือน behavior เดิมที่ก็ตัด token `--mood` แรกอยู่แล้ว) — acceptable, ไม่ถือ regression
- **EMOJI codepoint เดี่ยว**: ตาราง `EMOJI_MOOD` เลือกเฉพาะ emoji ที่เป็น single codepoint (ไม่มี variation selector / ZWJ) — `extract_mood` จึง iterate ทีละ `char` ได้ ถ้าอนาคตเพิ่ม emoji แบบ multi-codepoint ต้องแก้ scan logic (comment เตือนไว้ในโค้ด)
- **pytest = infra ใหม่**: `test_say_moods.py` วางที่ root (ไม่มี `tests/` layout ตาม convention script เดี่ยว) — unit test แรกของ repo, coding-style.md §Testing อนุมัติแนวทางนี้สำหรับ pure logic
- **total-char limit หลัง strip**: ผู้ใช้ที่พิมพ์ emoji เยอะอาจงงว่าทำไมนับได้น้อยกว่าที่พิมพ์ — error message ระบุ "หลังตัด emoji" ชัดเจน
- **sentence gap หลังทุก playback item**: รวม gap ระหว่าง `?say` คนละคำสั่งที่คิวติดกัน และ gap ก่อน idle-leave countdown เริ่ม (+0.5s ก่อนออกจากห้อง — negligible)
- **atomic batch**: generate บรรทัดที่ 5/5 fail = ทิ้งงาน gen บรรทัด 1-4 (เสีย compute) — ยอมรับได้ตาม decision, ทางเลือกอื่น (เล่นเท่าที่ได้) ผู้ใช้ปฏิเสธแล้ว
- **regression risk**: `say()` ถูกเขียนใหม่เกือบทั้ง function — ต้องผ่าน `code-review` (+ พิจารณา `security-review` เพราะแตะ path ที่ feed text เข้า `discord.FFmpegPCMAudio` / daemon — แม้ไม่มี shell) ก่อนเข้า done ตาม coding-style.md §Review Code

### Design Decisions (2026-08-30, brainstorming gate)

- **emoji → mood mapping**: ตารางที่ล็อกแล้ว 10 moods × 2-5 emoji (ไม่ map `default`/`long`)
  - `excited`: 😄 😁 😃 🎉 ⚡
  - `giggle`: 😆 🤣 😂 😹
  - `surprised`: 😮 😲 😯 😱
  - `sad`: 😢 😭 😔 💔
  - `angry`: 😠 😡 😤
  - `sleepy`: 😴 😪 🥱
  - `whisper`: 🤫 🤐
  - `gentle`: 🥺 🤗 💗
  - `bored`: 😑 😐 🙄
  - `storyteller`: 📖 📚 🧚
- **emoji detection**: เทียบตรงกับ keys ของ `EMOJI_MOOD` dict (scan หา emoji ตัวแรกที่เป็น key) — ไม่เพิ่ม dependency, ไม่ใช้ regex Unicode ranges / lib `emoji`
- **emoji ที่ไม่อยู่ในตาราง** (เช่น 🍕 ❤️): ปล่อยไว้ในข้อความ (TTS มักข้ามเอง), บรรทัดนั้น mood = default — ตัดเฉพาะ emoji ตัวที่ trigger mood เท่านั้น
- **MAX_CHARS**: เช็ค **total** ของทุกบรรทัดหลังตัด emoji + trim ≤ `MAX_CHARS` (300) → เกิน = reject ก่อนเข้าคิว (total ≤ 300 การันตีทุกบรรทัด ≤ 300 อยู่แล้ว ไม่ต้องเช็ค per-line)
- **generate/playback ordering**: generate ครบทุกบรรทัดก่อน (loop `_try_daemon` ใน `asyncio.to_thread`) แล้วค่อย queue N jobs ตามลำดับบรรทัด — worker/idle-leave เดิมไม่แตะ
- **partial failure**: บรรทัดใดบรรทัดหนึ่ง generate ล้มเหลว (daemon ล่มกลางคัน) → ลบ temp wav ทั้ง batch, ไม่ queue อะไรเลย, reply error ชัดเจน (atomic — policy เดียวกับ TTS-1001)
- **explicit `--mood` vs emoji**: `--mood <preset>` ที่พิมพ์เองชนะ emoji เสมอ; emoji ตัวที่เป็น key ยังถูก strip ออกจากข้อความพูดแม้ mood จะมาจาก `--mood`
- **silence gap** (เพิ่ม 2026-08-30 ตามคำขอผู้ใช้): เว้นเงียบ ~0.5s หลังจบทุกประโยค — `await asyncio.sleep(SAY_SENTENCE_GAP_S)` ใน `GuildPlayback._worker` หลัง `done.wait()` ก่อน dequeue ตัวถัดไป; env var `SAY_SENTENCE_GAP_S` (default `0.5`, `0` = ปิด); gap เกิดหลังทุก playback item รวมถึงระหว่าง `?say` คนละคำสั่งที่เข้าคิวติดกัน; ทำที่ layer playback ล้วน ไม่ pad wav
- **module layout**: pure logic แยกเป็น `say_moods.py` (`EMOJI_MOOD`, `parse_lines`, `extract_mood`) + `test_say_moods.py` (unit test แรกในโปรเจกต์ ตาม `coding-style.md`); `discord_say_bot.py` import มาใช้
