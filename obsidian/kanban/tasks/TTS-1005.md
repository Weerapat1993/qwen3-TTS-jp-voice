## 🟢 TTS-1005: /transcribe — อัปโหลดไฟล์เสียง วิเคราะห์เป็นข้อความ + emoji mood พร้อมใช้กับ /say

### Summary
เพิ่ม slash command `/transcribe` (ชื่อรอผู้ใช้ยืนยัน) ใน `discord_say_bot.py` — ผู้ใช้อัปโหลดไฟล์เสียง `.mp3`/`.wav` ระบบถอดเสียงเป็นข้อความ (speech-to-text) วิเคราะห์ mood ต่อช่วง/บรรทัด ใส่ emoji mood นำหน้า แล้วส่งกลับเป็น text ที่จัดรูปแบบพร้อมนำไปใช้กับ `/say file:` ได้ทันที (1 บรรทัด = 1 ประโยค, emoji auto-mood ของ say_moods.py)

### Context
- ต่อยอดจาก TTS-1001–1004: say-bot ปัจจุบันเป็น slash command `/say` (`text:` หรือ `file:` .txt) ทำงานบน `discord.Client` + `app_commands.CommandTree`
- Flow ใหม่: audio file → STT → แบ่งประโยคเป็นบรรทัด → ตรวจ mood ต่อบรรทัด (จากเสียง/น้ำเสียง หรือ heuristic จากข้อความ — ต้องตัดสินใจ) → เติม emoji จาก `MOOD_PRESETS`/`say_moods.py` mapping → reply เป็นข้อความ (และ/หรือ `.txt` file) ที่ paste กลับเข้า `/say file:` ได้เลย
- STT engine ต้องเลือก (Open Questions):
  - แนวทาง A: local ด้วย Whisper (เช่น `mlx-whisper` บน Apple Silicon — สอดคล้องธีม no-cloud ของโปรเจกต์, dependency ใหม่ ~1GB+ model)
  - แนวทาง B: ใช้ external API (มีต้นทุน + secret)
- แนวทาง mood: (a) ประเมินจากข้อความถอดเสียงด้วย keyword/heuristic อย่างง่าย หรือ (b) วิเคราะห์น้ำเสียงจากเสียงจริง (audio features — ซับซ้อนกว่ามาก) หรือ (c) ผู้ใช้ระบุ mood เองต่อไฟล์
- Output format ต้องเข้ากับท่อเดิม: `/say file:` → `parse_lines` → `extract_mood` (emoji นำหน้า) → `resolve_instruct` — หมายความว่า emoji ที่ใส่ต้องเป็น emoji ที่ `extract_mood` รู้จัก
- ปลายทางเดิม: TTS gen ผ่าน daemon (`_try_daemon`), คิว GuildPlayback — แต่ ticket นี้ output เป็น **text** อย่างเดียว (ไม่เล่นเสียง) ตามโจทย์ "จัดเรียงข้อมูลแบบ text /say ให้เลย"

### Scope
- `discord_say_bot.py`: เพิ่ม slash command ใหม่ (เช่น `/transcribe`) รับ option `file` (`discord.Attachment`, audio: .mp3/.wav, มี size cap), อาจมี optional `play` หรือ ส่ง text อย่างเดียวก่อน
- STT module ใหม่ (เช่น `stt_transcribe.py`) ใช้แนวทางที่ยืนยัน แล้ว return ข้อความ + segment timestamps ถ้ามี
- Mood/emoji assignment module: map ผล STT ต่อ segment → mood → emoji ที่ `extract_mood` รองรับ
- Output format: ข้อความหลายบรรทัด `😀 <ประโยค>` ต่อบรรทัด + ส่งเป็น `.txt` attachment ด้วย (สำหรับ paste กลับ `/say file:`)
- ไม่แตะ: `qwen_clone_tts.py`, `tts_daemon.py`, `GuildPlayback` (เว้นแต่ ticket ขยาย scope ให้เล่นเสียงทับใน VC ภายหลัง)

### Acceptance Criteria
- [ ] `/transcribe file:<audio.mp3|wav>` → bot ตอบกลับข้อความที่ถอดเสียงได้ + emoji mood นำหน้าแต่ละบรรทัด
- [ ] ผลลัพธ์ copy/paste ลงไฟล์ `.txt` แล้วใช้กับ `/say file:` ได้ทันที (emoji เดิน mood ให้ `extract_mood` ถูก)
- [ ] รองรับ `.mp3` และ `.wav` (ขยาย format ตาม STT engine); ไฟล์อื่น → reject ephemeral
- [ ] ขนาดไฟล์/ความยาวเสียงมีลิมิตชัดเจน (ระบุค่าตอน plan) → เกิน → ephemeral error
- [ ] daemon ล่มไม่มีผลกับ command นี้ (ไม่ใช้ TTS daemon)
- [ ] error/usage → ephemeral; ผลสำเร็จ → channel ปกติ
- [ ] ไม่เพิ่ม intent ใหม่; env var/dependency ใหม่ (ถ้ามี) อัปเดตใน README

### Validation
- ทดสอบ live: อัปโหลด .mp3/.wav จริงใน Discord → ได้ text + emoji ถูก mood
- ทดสอบ round-trip: ผลลัพธ์ → `/say file:` → เสียง Liino เล่นทีละบรรทัด พร้อม mood ตาม emoji
- ทดสอบ reject: ไฟล์ผิด type, เกินลิมิต, ไม่มีไฟล์

### Decisions (ผู้ใช้ยืนยันแล้ว, 2026-08-30)
1. **STT engine**: Whisper local — `mlx-whisper` (Apple Silicon, ธีม no-cloud เดิม); model โหลดครั้งแรก ~1GB+; แนะนำเริ่มที่ model เล็ก (เช่น `small`/`base`) ก่อน แล้วปรับตามคุณภาพภาษาไทย
2. **Mood**: วิเคราะห์จากข้อความถอดเสียง (keyword/heuristic) + option `mood:` ให้ผู้ใช้ override ทั้งไฟล์ได้
3. **ชื่อ command**: `/transcribe`
4. **ลิมิต**: ไฟล์ ≤ 20 MB และเสียง ≤ 10 นาที (เกิน → reject ephemeral)

### Open Questions (resolved 2026-08-30 ตอน brainstorming)
1. ~~โมเดล Whisper ขนาดไหน~~ → default `mlx-community/whisper-large-v3-turbo` (~1.6 GB, ~800M params, สมดุลความแม่นภาษาไทย/ความเร็วบน Apple Silicon), override ด้วย env var `TRANSCRIBE_WHISPER_MODEL`; lazy-load ครั้งเดียวใน bot process
2. ~~Output channel text vs `.txt`~~ → แนบ `.txt` เสมอ (paste เข้า `/say file:` ได้ทันที) + preview inline ในแชทเมื่อ body ≤ 1800 ตัวอักษร ไม่งั้นแนบไฟล์อย่างเดียว
3. (เพิ่มตอน brainstorming) reverse map `mood → canonical emoji` อยู่ที่ `say_moods.MOOD_EMOJI`; mood heuristic เป็น keyword/substring table ไทย+อังกฤษ ในโมดูล pure logic ใหม่ `transcribe_mood.py`
