## 🟢 TTS-1014: ปรับปรุงความเป็นธรรมชาติของ voice clone (ref clip + transcript + instruct + generation params)

Status: Done
Priority: High
Source: ผล voice-clone test (basti/liinonew TH+EN, TTS ออกมาถูกเสียงแต่ยังไม่เป็นธรรมชาติ) + research session 2026-09-03 (แนวทางจาก Qwen3-TTS official docs, faster-qwen3-tts, ComfyUI-Qwen3-TTS, Baseten fine-tuning blog)

### Summary

เสียง voice-clone ปัจจุบันได้ timbre ตรงแล้วแต่ prosody ยังฟังแข็ง/แบน ไม่เป็นธรรมชาติเหมือนพูดจริง Ticket นี้ปรับปรุงปัจจัยที่ research ชี้ว่ากระทบ naturalness มากที่สุด: (1) reference clip ที่ดี (10–15 วิ, มี intonation หลากหลาย, silence padding ท้ายคลิป), (2) transcript ของ ref audio ที่แม่นยำ (ICL mode เพิ่ม speaker similarity ~0.75 → ~0.89), (3) instruct ที่ระบุ pace/rhythm/pause ชัดเจน, (4) A/B validate ด้วย `tune_voice.py` ก่อน/หลัง เป็น gate

### Context

ผล research (2026-09-03, Qwen3-TTS naturalness):

- Ref audio sweet spot = **10–15 วินาที**; ยาวเกินเพิ่มความเสี่ยง generation hang/loop (โมเดลไม่ปล่อย EOS token) — ref ยาวไม่ได้แปลว่า "เรียนรู้เพิ่ม"
  - สถานะปัจจุบัน: `voices/liinonew.wav` = 12 วิ (โอเค), `voices/basti.wav` = 12 วิ (โอเค), `voices/Liino.wav` = 50 วิ (**ยาวเกิน — ควรตัดใหม่**)
- มี ref transcript ตรงกับเสียง (`ref_text` แม่น) เพิ่ม speaker similarity อย่างมีนัยสำคัญ — transcript ต้องตรงกับสิ่งที่พูดจริง ไม่ใช่คำอธิบายตัวละคร
  - ⚠️ สังเกต: `.txt` ปัจจุบันของบาง voice อาจไม่ใช่ transcript ของ ref clip (เช่น `liinonew.txt` เป็นประโยคภาษาญี่ปุ่น — ต้อง verify ว่าตรงกับเสียงใน `liinonew.wav` จริงหรือไม่)
- Artifact ที่พบบ่อย: คำแรกของ generated speech เพี้ยน เพราะ token แรก condition กับ phoneme ท้าย ref clip → fix = **เติม silence 0.5 วิ ต่อท้าย ref** ก่อน encode (แหล่ง: faster-qwen3-tts)
- Prosody ของผลลัพธ์สะท้อน prosody ของ ref — ref ที่อ่านเรียบจะได้ clone ที่เรียบ; ref ควรเป็นบทสนทนามี intonation หลากหลาย (official Qwen example ref text ใช้ประโยคอารมณ์เด้ง) แต่อารมณ์รวมสม่ำเสมอใน 1 คลิป
- Instruct ที่โมเดลฟังจริง 7 มิติ: gender/age/pitch/**pace**/emotion/characteristics/use-case — คำว่า "natural" ลอยๆ ไม่ช่วย; ต้องระบุ pace กับ rhythm เชิงปฏิบัติ (เช่น "occasional short pauses between sentences")
- Generation params ที่ Qwen ship: temperature 0.9, top_k 50, top_p 1.0, repetition_penalty 1.05 — สามารถทดลองปรับใน A/B ได้ แต่ไม่ใช่ lever หลัก
- ภาษาไทยไม่อยู่ใน 10 ภาษาที่โมเดลรองรับ (ใช้ auto) — naturalness ภาษาไทยจึงมีเพดานจากตัวโมเดลเอง ยอมรับใน Non-goals

สื่อที่มีแล้ว: `tests/Basti-Voice-36s.mp3` (36 วิ, ผู้ใช้ยืนยันว่าเป็น ref ตั้งต้นของเสียง Basti) — มีเนื้อหาพอให้เลือกช่วง 10–15 วิ ที่ดีที่สุด

### Scope

1. **ตัด ref clip ใหม่จาก `tests/Basti-Voice-36s.mp3`** → เลือกช่วง 10–15 วิ ที่เป็นบทสนทนาชัด มี intonation หลากหลาย ไม่มี noise ยาว (ffmpeg ตัดแบบ copy/re-encode ปกติ) → อัปเดต `voices/basti.wav`
2. **Transcript แม่นยำ**: ถอดเสียง ref clip ด้วย Whisper (ผ่าน `mlx-whisper` ที่มีใน dependencies อยู่แล้ว หรือ manual) → เขียน `voices/basti.txt` ให้ตรงกับเสียงจริง 100%
3. **Silence padding**: เติม silence 0.5 วิต่อท้าย ref clip ก่อนใช้ (script เล็ก หรือทำครั้งเดียวด้วย ffmpeg apad) — ตัดสินใจใน plan ว่าจะทำเป็น step ใน pipeline หรือครั้งเดียวต่อไฟล์
4. **ทำซ้ำข้อ 1–3 กับ `voices/Liino.wav`** (50 วิ → ตัดเหลือ 10–15 วิ + transcript ตรง) — แก้กรณี ref ยาวเกิน
5. **Verify `.txt`/`.instruct.txt` ของทุก voice** (basti, liinonew, Liino) ว่า `.txt` เป็น transcript จริงของ ref และ `.instruct.txt` มี pace/rhythm ชัด — ปรับ instruct ที่ขาด (เช่นเพิ่ม "natural conversational rhythm, occasional short pauses between sentences" แบบ objective)
6. **A/B validate ด้วย `tune_voice.py`**: เทียบ ref เก่า vs ใหม่ กับข้อความ test ชุดเดิม (TH + EN) สร้าง `outputs/tuning/<run_id>/results.md` สรุปผล
7. อัปเดต `README.md` (§ voice clone / ref audio guidelines) ด้วย best practice ที่ตกลงกัน (10–15 วิ, transcript แม่น, silence padding)

### Non-goals

- ไม่ทำ fine-tuning โมเดล (ต้อง GPU datacenter; ตัดสินใจระยะยาวต่างหาก)
- ไม่แก้ daemon protocol, cache, queue ใน `tts_daemon.py`
- ไม่รับประกันความเป็นธรรมชาติภาษาไทยระดับเดียวกับ EN/JA — โมเดลไม่รองรับภาษาไทย (constraint จาก upstream)
- ไม่เปลี่ยน mood presets ที่มีอยู่ (ยกเว้นถ้า A/B ชี้ว่าจำเป็น และต้อง A/B validate ตาม convention ของ mood ticket)

### Decisions

จาก `brainstorming` session (ก่อนเขียน plan นี้):

1. **Cache staleness** (พบระหว่าง pre-plan research: `_cache_key()` ที่ `tts_daemon.py:94-103` hash `voice name + text + instruct` เท่านั้น ไม่ hash เนื้อหาไฟล์ ref — swap `.wav` โดยไม่เปลี่ยนชื่อจะไม่ invalidate cache เดิม) → **จัดการด้วยการ clear `TTS_CACHE_DIR` ทั้งโฟลเดอร์แบบ manual หลัง swap แต่ละรอบ** ไม่แก้โค้ด `tts_daemon.py` (คง Non-goals เดิม) เหตุผลที่ clear ทั้งโฟลเดอร์แทนที่จะเลือกเฉพาะ entry: cache file ตั้งชื่อด้วย sha256 key ล้วน ไม่มี prefix ต่อ voice ให้ grep เลือกได้ และ cache เป็น derived data ที่ regenerate ได้เสมอ ความเสี่ยงต่ำ
2. **Silence padding**: ทำเป็น **one-off ffmpeg `apad` ต่อไฟล์** (basti/liinonew/Liino) เท่านั้น **ไม่แตะ `voice_store.py`** — `prepare_ref_audio()` (`voice_store.py:178-205`) ใช้กับ flow `/voice-clone create` ของ Discord bot ต่างหาก การเปลี่ยน permanent จะกระทบทุก voice ที่สร้างใหม่ในอนาคตและต้องมี test เพิ่มใน `test_voice_store.py` — เกินขอบเขต ticket นี้ (ตั้งเป็นไอเดียสำหรับ ticket แยกในอนาคตถ้าต้องการ)
3. **Liino rollout order**: `voices/Liino.wav` เป็น voice ที่ Hermes agent hardcode ใช้จริงผ่าน `--stdin` (ยืนยันจาก `README_HERMES.md`) — ทำ **basti/liinonew ก่อน + A/B validate ให้ user ฟังยืนยันว่าดีขึ้นจริงก่อน** แล้วค่อย backup (`voices/Liino.wav.bak`, `voices/Liino.txt.bak`) + swap Liino ทีหลังสุด พร้อม cache clear + validate แยกรอบ ก่อนถือว่า ticket เสร็จ
