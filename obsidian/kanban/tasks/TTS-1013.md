## 🟢 TTS-1013: /translate — upload audio, voice-clone, JP→EN/TH translate, TTS output

Status: Todo
Priority: Medium
Source: `/grill-with-docs` session (2026-09-03), design captured in `CONTEXT.md` + `docs/adr/0001-translate-mt-model-lives-in-bot-process.md` + `docs/adr/0002-translate-ephemeral-clone-reuses-voices-dir.md`

### Summary

New Discord slash command `/translate`: user uploads an audio file (`.mp3`/`.wav`), bot transcribes it (STT), translates the transcript to English and/or Thai via a local LLM, clones the uploaded speaker's voice ephemerally, and returns TTS audio of the translation(s) in that cloned voice plus the original transcript. Source/target languages are configurable per invocation, defaulting to auto-detect source and both EN+TH targets.

### Context

Read `CONTEXT.md` for the vocabulary this ticket uses (Voice, Ephemeral Voice, Reference Clip, Mood, Instruct, Source/Target Language, Transcript, Translation, Chunk) — don't re-derive definitions here. Read both ADRs for the two decisions a future reader would find surprising:

- ADR-0001: the MT model (`mlx-community/Qwen2.5-7B-Instruct-4bit`, ~4.5GB) loads as a lazy singleton inside `discord_say_bot.py`, not inside `tts_daemon.py`.
- ADR-0002: the ephemeral voice clone is written to `voices/_translate_<interaction_id>.wav` (a name `sanitize_name()` can never produce for a real Voice) and deleted in a `finally` block, rather than living outside `VOICES_DIR`.

### Decisions

(Full grilling record — 17 questions — lives in session history; the load-bearing ones not already covered by the ADRs/CONTEXT.md:)

- Command surface: Discord slash command only. No CLI/`qwen_clone_tts.py` flag equivalent.
- Translation engine: local `mlx-lm`, model `mlx-community/Qwen2.5-7B-Instruct-4bit`, fixed (not env-configurable).
- Upload limits: same as `/transcribe` — ≤20MB, ≤10 minutes, `.mp3`/`.wav` only.
- Reference clip: reuse `voice_store.prepare_ref_audio()` as-is (trims to `REF_TRIM_SECONDS`, currently 12s).
- Source/target language are runtime params, not fixed: `source_lang` (choice, default `auto`), `target_lang` (choice: `en` / `th` / `both`, default `both`).
- Translation runs once per target language, whole-Transcript-in-one-call (not per-segment) so the MT model has full-sentence context.
- Mood/instruct for each output: auto-detected via `detect_mood()` run separately per target language's Translation text (same pattern as `/transcribe`'s mood-emoji logic), not a manual param.
- Text over `MAX_CHARS` (300): chunking via the already-active `_run_multi()` path in `qwen_clone_tts.py` is enabled for `/translate` specifically (reuse, no new chunking code).
- Discord response: original Transcript (text) + one audio file per requested target language.
- Partial-failure policy when `target_lang=both`: if either language's translation or TTS step fails, fail the whole request — send nothing, report the error. No partial delivery.

### Scope

- New `translate_text.py` module: houses the `mlx-lm` singleton loader + `translate(text, target_lang) -> str` function. Pure module (no `discord` import), mirroring how `voice_store.py`/`say_moods.py`/`transcribe_mood.py` are structured, so it can be unit tested standalone.
- New `test_translate_text.py`: unit tests for `translate_text.py` (model-loading mocked/skipped as appropriate — follow whatever pattern `test_voice_store.py` uses for isolating slow/model-dependent code).
- `discord_say_bot.py`: new `/translate` command —
  - params: attachment (required), `source_lang` (choice, default auto), `target_lang` (choice: en/th/both, default both)
  - pre-defer validation: extension + size (reuse `/transcribe`'s and `/voice-clone create`'s existing validation pattern)
  - `defer(ephemeral=True, thinking=True)`
  - download attachment → `voice_store.prepare_ref_audio()` into `voices/_translate_<interaction_id>.wav`
  - `stt_transcribe.transcribe()` for the Transcript
  - `translate_text.translate()` per requested target language, building one Translation per language
  - `detect_mood()` per Translation → `resolve_instruct()`
  - TTS each Translation via `_run_multi()` (chunked), voice = the ephemeral clone's name
  - send Transcript text + generated audio file(s) via `interaction.channel.send()`, same zero-width-space escaping + `allowed_mentions=discord.AllowedMentions.none()` convention as `/transcribe`
  - `finally`: delete the ephemeral voice's `.wav` (and any `.txt`/`.instruct.txt` if created) regardless of success/failure
- `requirements.txt`: add explicit `mlx-lm` dependency (currently only transitive via `mlx-audio` — pin it directly since `translate_text.py` imports it directly for the first time).

### Non-goals

- No CLI/`qwen_clone_tts.py` entry point for translation — Discord-only per Decisions.
- No changes to `tts_daemon.py`'s JSON protocol or job queue (ADR-0001).
- No persistent/named voice created from `/translate` uploads — always ephemeral (ADR-0002); users who want a persistent clone still use `/voice-clone create`.
- No idle-unload or lifecycle management for the MT model — accepted RAM trade-off per ADR-0001, revisit only if it becomes a real problem.
- No per-segment translation — whole-document only, per Decisions.
- No partial delivery on `target_lang=both` failure — all-or-nothing, per Decisions.

### Acceptance Criteria

- [ ] `/translate` accepts an audio attachment, `source_lang` (auto/explicit), `target_lang` (en/th/both) and validates ext/size before deferring, matching `/transcribe`'s limits (≤20MB, ≤10min, `.mp3`/`.wav`).
- [ ] Uploaded audio is trimmed via `voice_store.prepare_ref_audio()` into an ephemeral voice file named `_translate_<interaction_id>.wav` under `voices/`.
- [ ] Transcript is produced via `stt_transcribe.transcribe()` using `source_lang` (or STT's own auto-detect when `source_lang=auto`).
- [ ] For each requested target language, the full Transcript is translated in one `mlx-lm` call (not per-segment) into that Translation.
- [ ] Each Translation's Mood is auto-detected independently via `detect_mood()` and resolved to an Instruct via `resolve_instruct()`.
- [ ] Each Translation is synthesized to audio via `_run_multi()` (correctly chunked when >300 chars) using the ephemeral voice, with `lang_code` set correctly per `LANG_CODES` (`"english"` for EN, `"auto"` for TH — TH has no dedicated `LANG_CODES` entry).
- [ ] Discord response contains the original Transcript text plus one audio file per successfully requested target language.
- [ ] If `target_lang=both` and either language's translation or TTS generation fails, no audio or partial transcript is sent — the whole request fails with a clear ephemeral error.
- [ ] The ephemeral voice's `.wav` (and any incidentally-created `.txt`/`.instruct.txt`) is deleted after the request completes, success or failure — verified no `_translate_*` files survive a normal run or a forced failure.
- [ ] `mlx-lm` is declared as a direct dependency in `requirements.txt`.
- [ ] `test_translate_text.py` covers `translate_text.py`'s public functions without requiring a real model download in CI (mock/skip pattern consistent with existing test file(s)).

### Implementation Plan

1. `translate_text.py`: lazy-singleton `mlx_lm.load("mlx-community/Qwen2.5-7B-Instruct-4bit")`, `translate(text, target_lang: str) -> str` building a chat-template prompt (`tokenizer.apply_chat_template` + `mlx_lm.generate`), one prompt per target language (`en`/`th`).
2. `test_translate_text.py`: unit tests around prompt construction / target-language dispatch, mocking the model call.
3. `discord_say_bot.py`: add `/translate` command following `/transcribe` and `/voice-clone create`'s existing shape (validation → defer → `asyncio.to_thread` for blocking STT/MT/TTS calls → cleanup in `finally`).
4. `requirements.txt`: add `mlx-lm` pin.
5. Manual validation pass (see Validation) — no daemon/CLI protocol changes needed, so no `tts_daemon.py`/`qwen_clone_tts.py` edits.

### Validation

- Manual: run `/translate` against a short JP voice clip with `target_lang=both`, confirm 2 audio files + transcript returned, audio is recognizably in the uploaded speaker's cloned voice.
- Manual: run with a Transcript long enough to force `_run_multi()` chunking (>300 chars translated), confirm concatenated output has no audible seams/gaps.
- Manual: force a mid-request failure (e.g. kill the daemon after STT but before second-language TTS) with `target_lang=both`, confirm nothing is sent to the channel and the ephemeral voice file is still cleaned up.
- `.venv/bin/python -m pytest test_translate_text.py` passes.
- Confirm no stray `voices/_translate_*` files remain in `voices/` after a normal run and after a forced-failure run.
